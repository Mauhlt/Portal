## How the rasters are made (all Zig)

`zig build brand` runs `src/tools/brand.zig`, which regenerates every
raster above; commit the results. Nothing outside Zig is involved:

- the icon is drawn by `src/tools/icon_art.zig`, the code version of
  `portal-icon.svg` (same geometry and colours), rasterised with 4×4
  (8×8 at ≤ 64 px) supersampling. It simplifies by size so it reads at
  16 px: below 256 px the ring and the orb grow (ring 30 → 78 units, orb
  60 → 104 units at 16 px), below 128 px the thin outer / inner rings go,
  below 96 px the constellation's lines, below 48 px its stars and the
  mountains;
- PNGs are written by `src/tools/pngw.zig` (adaptive filters, std's
  deflate at its best level); the `.ico` container is written by
  `brand.zig`;
- the hero JPEG is decoded by the owner's Image package.

`zig build ios` draws its bundle icons with the same code at build time
(`src/tools/ios_icon.zig`: AppIcon60x60@2x/@3x, 120 and 180 px, opaque).
The 1024 px icon here is for an asset catalog / App Store upload made on a
Mac (the Zig-only bundle has no `actool`, so the bundle lists the
`CFBundleIconFiles` PNGs).

## Where they are wired

- **Windows exe icon**: `build.zig` (`addAppIcon`) links `portal.ico` as
  icon resource 1 into `portal.exe`, `portalctl.exe` and both launchers
  (a one-line resource script generated by the build, compiled by Zig's
  own resource compiler).
- **Window icon** (title bar, taskbar, Alt-Tab): `Presenter.init` loads
  resource 1 and sends `WM_SETICON` (big and small). The Renderer's window
  class has no icon; the tidier fix there would be `.icon` / `.icon_small`
  = `LoadImageW(hinstance, 1, IMAGE_ICON, ...)` in its `WNDCLASSEXW`
  (`Renderer/src/Window/win32.zig`).
- **iPhone**: the bundle's `AppIcon60x60@2x.png` / `@3x.png` (Info.plist
  `CFBundleIcons`), drawn by `ios-icon`; the privacy cover is the theme's
  background.
- **Splash**: `Presenter.beginSplash(view.hero_png)` right after the
  window opens on the desk (`src/gui.zig`) and the laptop / iPhone
  (`client/src/connect.zig`); see "Splash" below.

(desk, laptop, iPhone; the terminal's 16 ANSI colours and the project tab
colours are derived from it). Contrast ratios are WCAG 2.x, against `bg`

- Every text colour is ≥ 7:1 on `bg` (AAA for body text; AA needs 4.5),
  UI lines ≥ 3:1.
- Red and green differ in lightness as well as hue (relative luminance
  0.33 vs 0.51), so Yes / No and errors / success stay apart for
  red–green colour blindness.
- The accent gradient (blue → cyan → green, as the ring runs top to
  bottom) underlines the active tab and the active top-bar button and
  edges Send / Instruct (`Frame.accentBar`); keyboard focus outlines are
  `ring_cyan`.
- Swipe cards: held = sun gold (`yellow`), towards Yes = meadow green,
  towards No = sunset red; a two-option (not Yes/No) card = `blue`.
- The project tab colours cycle through the twelve hues above.

## Splash

The hero art shows centred, scaled to fit (92% of the shorter side), on
`bg`, from the moment the window opens until the app is ready:

- desk: until the shown tab's first output (the session started);
- laptop / iPhone: until the client is connected or needs the user
  (pairing, a trust problem, an error); the first-run screen ends it at
  once.

It is shown for at least 0.9 s once drawn (no flicker) and at most 4 s
after start, and any key, click or touch ends it. It never delays
start-up: the PNG is decoded on its own thread (the window is woken when
it is done) and an undecodable PNG is skipped. Event-driven: one frame,
no animation; the only timeouts are those two real deadlines.

There is no About panel yet; when one is added, `view.hero_png` is the
art to use.
